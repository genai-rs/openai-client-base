# openai-server-base

[![crates.io](https://img.shields.io/crates/v/openai-server-base)](https://crates.io/crates/openai-server-base)
[![docs.rs](https://img.shields.io/docsrs/openai-server-base)](https://docs.rs/openai-server-base)

The OpenAI API as an [axum](https://docs.rs/axum) server: a trait per API group with a method per operation, a
request struct and a response enum per operation, and one router. It is generated by
[timvw-rust](https://github.com/timvw/openapi-generator-timvw-rust) from the same spec and with the same model options
as [openai-client-base](https://crates.io/crates/openai-client-base), whose models it uses: a server built on it and a
client built on openai-client-base exchange the same Rust types.

Its main use is [openai-mock-server](https://crates.io/crates/openai-mock-server), a scripted mock of the OpenAI API
for tests. Every trait method has a default that answers `501 Not Implemented`, so an implementation implements only
the operations it serves:

```rust,ignore
use openai_server_base::server::{self, chat_api, ServerError};

#[derive(Clone)]
struct Api;

impl server::ErrorHandler for Api {}
impl server::ChatApi for Api {
    async fn create_chat_completion(
        &self,
        request: chat_api::CreateChatCompletionRequest,
    ) -> Result<chat_api::CreateChatCompletionResponse, ServerError> {
        // request.body is an openai_client_base::models::CreateChatCompletionRequest
        todo!()
    }
}
// impl server::<Trait> for Api {} for every other trait: their operations answer 501

let app: axum::Router = server::router(Api);
```

- **Requests** that do not decode (a missing parameter, a body that is not its model, a media type the operation does
  not take) are answered by `ErrorHandler::invalid_request` without calling the implementation.
- **Bodies:** JSON models, event streams (`server::EventStream`, written as OpenAI writes them, with `event:` names on
  Responses streams), multipart forms with `server::FilePart`s, bytes (`server::Binary`) and text.
- **Cargo features** are openai-client-base's API groups (`chat-completion`, `responses`, `file`, ...; `full` by
  default): a group compiles its operations and enables the models it needs.
- Not served yet: the operations listed at the end of [`server`](https://docs.rs/openai-server-base/latest/openai_server_base/server/)
  (deepObject query parameters, multipart fields that are a file or a reference).

The code is regenerated with openai-client-base (`scripts/generate.sh`); only this README and `Cargo.toml` are written
by hand.
