# openai-client-base 0.18.0 → 0.19.0: `Default` only where valid, `FromStr` on enums, no struct `Display`

This release generates with `timvw-rust` 0.11.0 and its `defaultOnlyWhereValid`, `enumFromStr` and `noStructDisplay`
options (Milestone 3.2 of the
[generator design](https://claude.ai/artifact/ABar8Up91gjVMDHgHL1GE3)). The OpenAI spec is unchanged.
The machine-readable census is `api-diff-0.18.0-to-0.19.0.json` in this folder.

## What stays the same

- Every type, field, variant and function keeps its name and type.
- The JSON on the wire is the same: `src/apis` is unchanged and no serde attribute changes.
- Constructors (`new`) and builders take the same arguments.

## What changes

### `Default` only where the API would accept the value

- A struct derives `Default` only when it has no required field. A required nullable field counts as required.
  1366 structs lose `Default` and 48 regain it, which leaves 319 with it.
- No enum implements `Default`, unions included. The 2,435 impls picked the first variant, which was not the API's
  default. Schema defaults are still not applied.
- Some of the regained structs were stripped by a name-based heuristic in 0.18.0 and earlier, which treated a local
  type as missing `Default` when another file's type of the same name lacked it.

### Closed enums parse from strings

- 2,240 closed enums implement `FromStr`, `TryFrom<&str>`, `TryFrom<&String>` and `TryFrom<String>`. They accept
  exactly the strings their `Display` prints. Unions do not get these impls.
- Failures return the new `models::ParseEnumError`, with `type_name()` and `value()` accessors.
- Enums defined inside a struct's file (such as `create_image_request::Quality`) had no `Display`. 1,903 of them gain
  one that prints their JSON name.

### Structs have no `Display`

- The 2,142 JSON `Display` impls on structs are gone. Enum `Display` stays, and untagged unions keep theirs.

## Migrating

- `T::default()` or `..Default::default()` on a struct with required fields: use `T::new(..)` or the builder, which
  require those fields at compile time.
- `#[derive(Default)]` on your own type holding one of these structs or an enum by value: write the `Default` impl and
  choose the value yourself, or hold an `Option`.
- `value.to_string()` on a struct: use `serde_json::to_string(&value)?`, which gives the same text.
- Your own `match` on a string to build an enum: use `"hd".parse::<create_image_request::Quality>()`.
